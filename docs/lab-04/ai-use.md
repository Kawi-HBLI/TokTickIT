## My Reflection

Gemini helped me turn the Lab 4 requirements into a specification and implement both the backend and frontend. I used Codex to review the proposed changes independently. Comparing their suggestions with the existing code helped me preserve the original status transitions and API response formats.

I learned that correct-looking code still needs tests for failure cases and concurrent requests. The reviews helped catch inconsistent audit records, stale updates, and a parent refresh that closed the action dialog and lost the user's draft. Keeping the dialog mounted during background refresh fixed that problem.

Another lesson was keeping an uncertain request's payload together with its idempotency key. If refreshing data fails, the original request has to stay available for retry. Testing disaster recovery and dashboard navigation also taught me the value of end-to-end rehearsal. Testing against an isolated recovery database and real browser viewports caught real integration gaps that unit mocks never would've shown.
